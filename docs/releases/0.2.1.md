# Driftless Bundle Photometry 0.2.1

Driftless Bundle Photometry 0.2.1 adds reproducible distribution and release
automation. It does not change the scientific acquisition or canonical NWB data
contracts introduced in 0.2.0.

## Highlights

- End users on 64-bit Windows receive one versioned Setup executable that includes
  Python, Qt, HDF5, PyNWB, the NDX extensions, and normal application dependencies.
- The per-user installer does not require administrator access and has Start menu,
  optional desktop shortcut, and Windows uninstall integration.
- Developers receive one Conda recipe that creates the `dbf` environment and installs
  the checkout editably with GUI, test, lint, build, and release tools.
- A published GitHub release validates the `v<version>` tag against package, README,
  and changelog metadata; builds and verifies wheel/source/Windows artifacts;
  publishes the Python artifacts to PyPI; attaches SHA-256 checksums; and creates
  GitHub provenance attestations when the repository plan supports them.

## Validation

- 171 automated tests pass locally on Python 3.13.
- Ruff lint and formatting checks pass.
- Wheel and source distributions build successfully and pass strict Twine metadata
  validation; the GUI wheel installs and imports outside the checkout.
- A local frozen application build loads the packaged GUI resources and completes a
  one-frame canonical NWB acquisition.
- The release workflow will additionally require a Windows frozen-app NWB smoke test
  plus silent installer install, launch, and uninstall before publication. Do not
  describe the Windows package as release-validated until that workflow passes.

## First-publish requirement

Repository/package owners must register the `pypi` Trusted Publisher described in
[the release guide](../releasing.md). The protected workflow uses short-lived
identity credentials; it does not store a PyPI token.

## Important boundaries

The installer is currently unsigned, so Windows SmartScreen may identify it as an
unknown publisher. This remains a software-validated release and does not establish
physical validation of the Thorlabs camera, controller/electronics, or live RWD
stream. Existing hardware-evidence requirements remain unchanged.
