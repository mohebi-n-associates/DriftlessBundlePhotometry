# Driftless Bundle Photometry 0.2.0

Driftless Bundle Photometry 0.2.0 is a substantial software reliability and RWD
read-only streaming release. It preserves the existing simulator/native workflow
while adding an end-to-end, trace-first RWD acquisition path.

## Highlights

- Choose native/simulator or RWD read-only acquisition at session setup.
- Map RWD device channels explicitly to stable fibers, labels, and animal metadata.
- Stream 410/470/560 fluorescence and named ON/OFF events through a bounded,
  observable acquisition path.
- Display asynchronous per-fiber raw, elapsed-time-smoothed, and dF/F traces without
  changing acquired or stored values.
- Produce one independently validated NWB file per mapped fiber/animal with exact
  raw ticks, raw vendor values, configured scales, named events, settings, and runtime
  provenance.
- Recover interrupted native and RWD sessions idempotently without silently replacing
  mismatched canonical files.
- Capture, checksum, inspect, and replay exact RWD TCP bytes through the production
  decoder, recovery spool, and NWB finalizer for physical bench validation.
- Surface acquisition faults, invalid spans, queue pressure, write latency, dropped
  frames, decoder counts, event activity, and finalization progress.

## Compatibility

- Python 3.11–3.13.
- Windows: simulator, RWD bridge, GUI, NWB, and best-effort physical camera boundary.
- macOS: simulator, RWD bridge/replay, GUI demo, NWB, and analysis workflow.
- Settings format v2; settings-v1 files migrate explicitly to the native source.
- Native spool schema v1 remains recoverable with an explicit provenance limitation;
  current native and RWD writers use their documented current schemas.

## Validation

- 164 automated tests pass locally on Python 3.13.
- Ruff lint and formatting gates pass.
- Golden NWB, PyNWB validation, NWB Inspector, reopen, exact-count, recovery, GUI,
  synthetic TCP, corruption, and wheel-packaging paths are covered.
- GitHub Actions exercises Windows and macOS on Python 3.11, 3.12, and 3.13, plus
  isolated core and GUI wheel smoke tests.

## Important hardware boundary

This is a software-validated release, not a claim that the physical camera,
controller/electronics, or RWD stream has been bench-validated. RWD remains the
hardware controller; DBF only reads its fluorescence/event TCP stream. The real RWD
preamble, timestamp unit, value scale, channel numbering, event padding, disconnect
behavior, and sustained capacity still require capture with the physical system.
Behavior video is not included.

Use the [RWD operator and bench-validation guide](../rwd-operator-guide.md) to retain
the exact wire evidence needed for that validation. Simulator or synthetic-server
success must not be presented as physical hardware evidence.
